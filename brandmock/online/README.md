# BrandMock Online 0.5

React/TypeScript/Konva + OpenCV.js, IndexedDB и JSZip. Онлайн-редактор размещает оригинальный логотип **на выбранной грани с перспективой**. Отдельного плоского наложения в интерфейсе нет. Фотографии не отправляются на сервер, исходные файлы не изменяются.

Рабочая публикация: https://kontora03-ship-it.github.io/garuss-proposals/brandmock/app/

## Работа

1. Загрузите фотографию JPG/PNG/WebP и логотип SVG/PNG/WebP/JPG. Их можно заменять независимо.
2. Приложение предложит плоскую грань. Другую можно выбрать кликом или из списка.
3. Если грань не найдена, нажмите **«Указать 4 угла»** и отметьте четыре угла нужной поверхности. Порядок обхода определяется автоматически. Рамка и логотип появляются только после выбора действительной грани. До этого видна исходная фотография, экспорт брендированного изображения отключён.
4. Подвигайте логотип крестиком, поправьте углы, масштаб и поворот. Кнопка «Повернуть на 90°» помогает выбрать ориентацию рисунка.
5. При необходимости откройте «Уточнить пропорции грани»: это одно отношение сторон без миллиметров. Эта настройка меняет модель плоскости, сохраняя исходные пропорции логотипа в её координатах.
6. Скачайте PNG, до/после или ZIP-проект с оригиналами и JSON. PNG всегда в исходном разрешении с учётом EXIF; до/после имеет двойную ширину. Вспомогательные рамки в экспорт не входят.

Пример «Тёмная коробка» — авторская синтетическая сцена со слабым контрастом между крышкой и боковинами, похожая по ракурсу на сообщённый сбой. Это **не фотография пользователя**. Пример «Наклонная грань» имеет известную синтетическую камеру. Источники и лицензии перечислены в public/samples/SOURCES.md.

## Как определяется грань

Поиск рассматривает замкнутые контуры и длинные рёбра во всех проходах, даже если уже найден общий силуэт изделия. Используются несколько порогов Canny, локальное усиление контраста без изменения оригинала, HoughLinesP и аппроксимация контуров. Поддержка каждого ребра проверяется по силе и направлению исходного градиента. Это отсеивает ложные линии от текстуры. При однородном фоне отвергаются рамки, захватывающие значительную часть фона. Направление осей грани выбирается так, чтобы надпись была по возможности ориентирована слева направо, а не случайно повёрнута на четверть оборота.

Поиск остаётся геометрической эвристикой. Он не является семантическим распознаванием изделия, полной 3D-реконструкцией или цилиндрической развёрткой. Складки, блики, перекрытия и изогнутые поверхности могут потребовать ручной разметки или отдельного будущего движка. Грань не подменяется фиктивным прямоугольником при отказе поиска.

## Геометрия нанесения

Логотип вписывается с исходным отношением сторон в координатах поверхности, затем `warpPerspective` проецирует его на фото. Premultiplied alpha защищает края от тёмных ореолов. За пределами покрытия сохраняются декодированные пиксели фотографии.

При устойчивой геометрии прямоугольной грани оцениваются камера и отношение сторон по ортогональности направлений рёбер. Модель предполагает квадратные пиксели, главную точку в центре кадра, отсутствие значительной дисторсии и скоса матрицы камеры. Кроп и неизвестная оптика нарушают эти предположения.

Если строгая калибровка невозможна, логотип всё равно проецируется на выбранную грань с **явно обозначенной приблизительной оценкой** пропорций. Используется камера с условным фокусом 0.85 диагонали кадра; это допущение, не восстановленный параметр камеры и не физическое измерение. Уточнить отношение сторон можно одним числом. Точную геометрию произвольной поверхности по одному неизвестному фото приложение не обещает.

## Подготовка JPG-логотипа

В «Подготовка JPG / логотипа» можно убрать однотонный фон, изменить допуск и мягкость, включить внутренние области букв и перекрасить рисунок. По умолчанию удаляются только связанные с краем области. Удаление внутренних областей затрагивает любые элементы выбранного цвета — проверяйте предпросмотр.

Это редактируемая растровая маска, без векторизации и генеративной перерисовки. Отдельный прозрачный PNG доступен даже без выбранной поверхности изделия. Оригинальный JPG сохраняется неизменным в ZIP. Четыре режима нанесения — печать, серебро, золото, блинт — остаются воспроизводимыми визуальными имитациями.

## Сохранение и совместимость

Проекты хранятся в IndexedDB этого браузера/профиля/домена. Очистка данных сайта удалит их. Скачивайте ZIP для резервной копии и переноса. Облачной синхронизации нет.

Новые ZIP используют JSON версии 5: выбранные углы, состояние поверхности, отношение сторон, положение и настройки маски/материала. Онлайн-редактор открывает версии 1–5. Старые сохранённые проекты в плоском режиме при первом открытии повторно анализируются новым детектором; исходники и маска сохраняются. После неудачного поиска требуется выбрать грань. Старые явно заданные пропорции плоскости преобразуются в отношение сторон. Временный список других кандидатов можно восстановить повторным автопоиском. Локальный Python-прототип открывает только JSON версии 1 и явно отклоняет новые архивы.

При смене проекта/фотографии старое изображение снимается с холста сразу; запоздалые запросы не могут заменить актуальный результат. Индикатор обработки учитывает декодирование изображения, чтобы старая фотография с новой рамкой не выглядела как готовое нанесение.

## Ограничения файлов

Файл до 20 МБ, фото до 12 Мп, ZIP до 25 МБ. Большие изображения могут замедлять интерфейс. SVG поддерживает безопасное подмножество без CSS/scripts/image/use/внешних ресурсов и растрируется до 1600 px. Текст зависит от системных шрифтов; для точности переводите в кривые. ICC/CMYK-цветопроба не поддерживается. Canvas может нормализовать скрытый RGB полностью прозрачных пикселей; оригинальный файл в архиве остаётся неизменным. Результат не обязан совпадать побайтно с Python-версией.

OpenCV.js (~11 МБ) размещён вместе с приложением; платных API нет. Лицензии — THIRD_PARTY.md.

## Разработка и проверки

```sh
npm ci
npm test
npm run dev -- --port 5174
# в другом терминале
npx playwright install chromium
npm run test:e2e
npm run build
```

Сборка — dist; публикация на GitHub Pages — содержимое dist в brandmock/app/. Исходники — brandmock/online/. Для другого адреса тестирования задайте BRANDMOCK_TEST_URL, для другого Chromium — BROWSER_EXECUTABLE. Артефакты браузерных тестов пишутся в игнорируемую test-artifacts/.

Тесты проверяют alpha/маски, исходные пиксели вне покрытия, воспроизводимость, перспективную геометрию и сохранение пропорций в координатах грани, точную синтетическую калибровку и явную приблизительную оценку без перехода к плоскому наложению. Браузерный регрессионный сценарий проверяет:

- поиск именно крышки тёмной коробки с ошибкой углов менее 15 px относительно авторского эталона;
- корректную ориентацию осей надписи, drag, поворот, уточнение пропорций и ZIP;
- автоматическую миграцию старого плоского проекта с типовым прямоугольником;
- отсутствие фиктивного результата и блокировку экспорта при отказе поиска;
- ручную разметку четырьмя кликами с немедленной перспективой;
- выбор другой грани, сохранение обработки реальной фотографии бумажного пакета;
- соответствие видимого холста актуальному тёмному изделию после смены фотографии;
- отсутствие ошибок консоли.

Pillow и NumPy нужны только для необязательной генерации тестовых сцен (`test/create-dark-box.py`); Python не требуется для работы сайта. Точная исходная фотография из пользовательского скриншота не получена: регрессионная сцена повторяет характер геометрии и слабого контраста, но не доказывает успешный поиск на каждом фото такого изделия.
